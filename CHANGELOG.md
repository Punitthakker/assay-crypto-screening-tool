## 0.7.0 - 2026-11-06
- Historic freeze event index (`packages/datasources/src/adapters/freeze-events.ts`, `pnpm index:freeze`): reads the issuer contracts' own blacklist logs into a local table per token, `data/freeze-index/<chain>-<symbol>.json`. Tether `AddedBlackList` / `RemovedBlackList` / `DestroyedBlackFunds` (address in `data`, burn amount decoded), Circle `Blacklisted` / `UnBlacklisted` (address in `topics[1]`). Providers behind `Transport`: Etherscan V2 `getLogs` with a key, the hosted Blockscout `/api` without one, TronGrid contract events for Tron. Incremental from a stored cursor, full pages resumed at the last block seen and deduped, a provider error aborts the run without touching the file. Solana has no freeze log and is skipped with a reason; USDT0 and bridged tokens too.
- `FreezeIndex` read side: per-address history (ever frozen, still listed per index, first add, release, destroyed amount) and per-token coverage with age. `--status` prints what is indexed. `CR_FREEZE_INDEX=0` switches it off, `CR_FREEZE_INDEX_DIR` moves it.
- Trace: an unlabelled counterparty the issuer once froze and released is `previously_frozen` (SCORING.md 2a, 20 points x decayed share, `EXPOSURE_PREVIOUSLY_FROZEN`); when the live freeze read is unavailable and the index still lists the address, the node counts as `frozen`. Nodes carry `freezeHistory`; `/v1/lookup` sources and the /check page show `previously_frozen` in amber.
- Sender: `EXPOSURE_DIRECT_PREVIOUSLY_FROZEN` (20 points, hop 0) with add and release dates and burned amount when the sender itself was blacklisted and released; `FREEZE_LISTED_PER_INDEX` info line and `FREEZE_INDEX_SAYS_LISTED` flag when the live read failed and the index still lists it (no points, question 11). A currently frozen sender stays `HB_FROZEN`. New `freeze-index` coverage line (`ok` with age, `unavailable` when no table exists, `not_applicable` on Solana and bridged tokens, `disabled`); it never changes confidence.
- Scoring version 1.1.0: one new row, the sender-level previously frozen at 20; no other weight or band changed.
- 21 new fixture tests (136 total): event sets and selectors, Tron address forms, Etherscan build from genesis with amount decode, cursor resume and dedupe, full-page walking, provider error, Blockscout keyless fallback with Circle's indexed topic, missing-provider reasons, TronGrid fingerprint paging and timestamp cursor, the read side (released versus listed, never frozen versus not indexed, coverage age), four tracer cases, four engine cases end to end on `data/fixtures/freeze-index/` (example 3 plus a released hop-2 wallet scores 14; a released sender scores 28 LOW; a frozen sender stays BLOCK; no index is stated and costs nothing).

## 0.4.0 - 2026-11-03
- 2-hop backward trace (`packages/engine/src/trace.ts`). Hop 1 is the sender's inbound transfers already fetched by the explorer adapters; hop 2 fetches the same for every unlabelled hop-1 counterparty through the same `ExplorerRouter`. Every node is classified by label store, OFAC list and issuer freeze read (freeze reads skipped for nodes a label or the list already settles, capped at 50 per trace). Exposure per category is the value share that flowed through tainted nodes, decayed by hop (1.0, 0.5, 0.25), mapped to points with the SCORING.md 2a weights and caps, dust rule floor of 8 for sanctioned, mixer and frozen. One `EXPOSURE_<CATEGORY>` risk line per category naming the top three contributors with tx hashes, plus a `FLOW_TRACE` info line.
- Boundaries: licensed exchange wallets end the branch at 0 points; labelled, frozen or sanctioned nodes contribute and are not expanded; loops back to the sender or a hop-1 wallet are `internal`; value beyond the fan-out cap (25 per hop) or behind a failed hop-2 fetch is `untraced`; a counterparty under the dust floor (1 token unit) is dropped so dusting cannot poison the trace.
- `fund-flow` coverage is now real: `ok` on a full trace, `partial` when untraced is above 20 percent, a hop-2 fetch failed, hop 1 was capped by the explorer, or the trace stopped at depth 1 with unlabelled counterparties left; `unavailable` when no explorer answered; `not_applicable` for a hard-blocked sender (trace skipped); `disabled` at depth 0 or with the explorer off. Confidence `high` is reachable for the first time.
- `POST /v1/lookup` and the /check page carry `trace` (nodes with hop, status, weight, parent, tx hashes; exposure; untraced; boundary). The source list reuses the trace's hop-1 answers so no freeze read runs twice.
- Env: `CR_TRACE_DEPTH`, `CR_TRACE_FANOUT`, `CR_TRACE_EXPAND_CAP`, `CR_TRACE_DUST`, `CR_TRACE_FREEZE_CAP`; request field `traceDepth` overrides per call.
- Fixes found on the way: `CONFIDENCE_*` flags were pushed after `computeScore` copied the flag list and never reached the report; OFAC snapshot age is pinned to 0 in fixture mode so fixture tests do not drift to `low` confidence as the recording ages; EVM freeze and oracle reads lowercase the address before ABI encoding so a mixed-case address with a wrong checksum no longer throws.
- 21 new fixture tests (80 total): 16 on hand-built graphs covering SCORING.md examples 3 and 4, decay, boundary, fan-out, dust, loops, depth, freeze cap; 5 end to end through the engine on `data/fixtures/trace.json`. Scoring version unchanged (1.0.0): weights, caps and bands are as published, only now evaluated.
