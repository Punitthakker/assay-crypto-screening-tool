# Changelog

## 0.6.0 - 2026-11-05
- Label import (`packages/datasources/src/adapters/label-import.ts`, `pnpm import:labels`): pulls public address-label datasets over `Transport.fetchText`, parses them into the local `Label` shape and writes `data/labels/imported-<id>.json` plus a `data/label-imports.json` manifest (URL, licence, fetch time, rows, kept, skipped reasons, duplicates). Sources: ImMike/crypto-wallet-address-labels forta phishing (6,205 scam addresses), forta malicious contracts with their named deployers (756), blockchain-unit and etherclust exchange wallets (86, gated by the VASP register). ScamSniffer (GPL-3.0) is opt-in only and lands in the git-ignored `data/labels-optional/`. MetaMask eth-phishing-detect turned out to be a domain list and is not imported.
- `data/vasps.json`: 33 VASP entities with jurisdiction, licence and a `licensed | unlicensed | unknown` status, validated by zod. The importer maps exchange wallet names onto it (`entityKey`, `matchVasp`, longest alias wins, names ending in `?` never match) and labels `exchange_licensed` (trace boundary) or `exchange_unlicensed` (20 points at full share); unknown entities are skipped, not guessed.
- `data/labels/mixers.json` (18 Tornado Cash pools) and `data/labels/bridges.json` (9 bridge contracts), both flagged for etherscan confirmation in VERIFY.md step 6.
- `LabelStore`: deterministic load order (name order, `seed.json` last so hand-kept entries win), `files` summary, optional extra directories via `CR_LABELS_EXTRA_DIR`. String constructor still accepted.
- `docs/LICENCES.md`: every dataset in the default path, opt-in, or looked at and rejected, with the licence read from each repository today.
- 15 new fixture tests (115 total): CSV parser, entity matching, each parser's keep and skip rules, dedupe, source policy (default-enabled sources are MIT, ScamSniffer off), `vasps.json` validation, import through a stub Transport including a fetch failure, store load order and extra dirs, and the committed store end to end. Scoring version unchanged (1.0.0): labels feed the existing weights.

## 0.5.0 - 2026-11-04
- Behavioural signals (`packages/engine/src/behaviour.ts`), the eight SCORING.md 2b lines, cap 35: `BEHAV_FRESH_WALLET` (first tx under 7 days), `BEHAV_LOW_TX_COUNT` (under 5), `BEHAV_DORMANT_REACTIVATED` (quiet 180 days then active in the last 7), `BEHAV_PASS_THROUGH` (median in-to-out hold under 10 minutes over the latest 20 outbound, at least 5 pairs), `BEHAV_STRUCTURING` (5 or more transfers in 30 days in the 5 percent band under 1,000 / 3,000 / Travel Rule threshold / 10,000), `BEHAV_CONCENTRATION` (over 70 percent of inbound from one unlabelled counterparty), `BEHAV_CONTRACT_ADMIN` (unverified contract that is a proxy or has an owner), `BEHAV_DRAINER_APPROVAL` (Approval to a `scam` or `darknet` labelled spender, SPL delegate on Solana). Suppressed for licensed VASP senders, skipped for hard-blocked senders, `CR_BEHAVIOUR=0` switches them off.
- Account activity adapter (`packages/datasources/src/adapters/activity.ts`) behind Transport: Etherscan V2 `txlist` (first tx, latest 25), `getsourcecode`, `getLogs` Approval; Blockscout address, counters and transactions when keyless; `eth_getTransactionCount` and `eth_getCode` on the public RPC with an `owner()` probe on contracts; TronGrid `/v1/accounts` and Tronscan `accountv2`; Helius enhanced transactions. Every field is independently nullable and the `behaviour` coverage line names each signal that could not be evaluated.
- Explorer adapters gained the outbound side (`outboundTransfers`, same window and cap). Etherscan and Helius serve both directions from one page; Blockscout uses `filter=from`, TronGrid `only_from`, Tronscan `fromAddress`.
- `Transport.evmGetTransactionCount` (fixture key `nonce:<chain>:<address>`); Solana token accounts now carry `delegate`.
- New `behaviour` coverage line: `ok`, `partial` (stated, no confidence downgrade), `unavailable` (caps confidence at medium), `not_applicable`, `disabled`. `/v1/lookup` responses carry `behaviour` facts (wallet age, tx count, median hold, top counterparty share, structuring hits, not-evaluated list).
- 20 new fixture tests (100 total): 15 on hand-built inputs covering every signal, its edges and the cap; 4 end to end on `data/fixtures/behaviour.json` (SCORING.md example 1 at 16 CLEAR high; a Tron mule at 33 LOW); 1 on the outbound explorer side. Scoring version unchanged (1.0.0): the 2b weights and the 35 cap are as published, only now evaluated.

## 0.4.0 - 2026-11-03
- 2-hop backward trace (`packages/engine/src/trace.ts`). Hop 1 is the sender's inbound transfers already fetched by the explorer adapters; hop 2 fetches the same for every unlabelled hop-1 counterparty through the same `ExplorerRouter`. Every node is classified by label store, OFAC list and issuer freeze read (freeze reads skipped for nodes a label or the list already settles, capped at 50 per trace). Exposure per category is the value share that flowed through tainted nodes, decayed by hop (1.0, 0.5, 0.25), mapped to points with the SCORING.md 2a weights and caps, dust rule floor of 8 for sanctioned, mixer and frozen. One `EXPOSURE_<CATEGORY>` risk line per category naming the top three contributors with tx hashes, plus a `FLOW_TRACE` info line.
- Boundaries: licensed exchange wallets end the branch at 0 points; labelled, frozen or sanctioned nodes contribute and are not expanded; loops back to the sender or a hop-1 wallet are `internal`; value beyond the fan-out cap (25 per hop) or behind a failed hop-2 fetch is `untraced`; a counterparty under the dust floor (1 token unit) is dropped so dusting cannot poison the trace.
- `fund-flow` coverage is now real: `ok` on a full trace, `partial` when untraced is above 20 percent, a hop-2 fetch failed, hop 1 was capped by the explorer, or the trace stopped at depth 1 with unlabelled counterparties left; `unavailable` when no explorer answered; `not_applicable` for a hard-blocked sender (trace skipped); `disabled` at depth 0 or with the explorer off. Confidence `high` is reachable for the first time.
- `POST /v1/lookup` and the /check page carry `trace` (nodes with hop, status, weight, parent, tx hashes; exposure; untraced; boundary). The source list reuses the trace's hop-1 answers so no freeze read runs twice.
- Env: `CR_TRACE_DEPTH`, `CR_TRACE_FANOUT`, `CR_TRACE_EXPAND_CAP`, `CR_TRACE_DUST`, `CR_TRACE_FREEZE_CAP`; request field `traceDepth` overrides per call.
- Fixes found on the way: `CONFIDENCE_*` flags were pushed after `computeScore` copied the flag list and never reached the report; OFAC snapshot age is pinned to 0 in fixture mode so fixture tests do not drift to `low` confidence as the recording ages; EVM freeze and oracle reads lowercase the address before ABI encoding so a mixed-case address with a wrong checksum no longer throws.
- 21 new fixture tests (80 total): 16 on hand-built graphs covering SCORING.md examples 3 and 4, decay, boundary, fan-out, dust, loops, depth, freeze cap; 5 end to end through the engine on `data/fixtures/trace.json`. Scoring version unchanged (1.0.0): weights, caps and bands are as published, only now evaluated.

## 0.3.0 - 2026-11-02
- Screen by transaction or explorer link (requested by Punit). One search box on /check accepts an address, a tx hash, a tronscan / etherscan-family / blockscout / solscan address link, or a tx link. `POST /v1/lookup` resolves it, screens the sender of that exact transfer (amount and token contract taken from the tx, so the fake-token hard block and the Travel Rule floor apply), confirms the tx pays the stated receiver, and lists the sender's sources: inbound counterparties over the 90-day window, aggregated by value, each checked against labels, OFAC and the issuer freeze list (top 10). Sources are informational; nothing moves the score until the 2-hop trace lands.
- Tx resolution: EVM via the public RPC receipt (Transfer logs, no key), Tron via TronGrid events, Solana via RPC getTransaction token balance deltas. `Transport.evmGetTransactionReceipt` added with a fixture key.
- `tronHexToBase58` in shared. `CR_FIXTURE_FILE` env to point fixture mode at another recording.
- 18 new fixture tests (55 total). Scoring version unchanged (1.0.0).
