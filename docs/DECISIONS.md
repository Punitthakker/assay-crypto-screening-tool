# Decisions log

Format: date - decision - reason - status (default | confirmed by Punit)

- 2026-11-01 - Product name stays a placeholder ("Clean Receive"); neutral brand with "Powered by MoneyBee" in the footer - exchanges should not see a PSP competitor's logo on their compliance screen - default
- 2026-11-01 - v1 chains: Ethereum, Tron, Solana, Base, Arbitrum One, Polygon PoS, Avalanche C-Chain, BNB Chain. Optimism registry-ready but off. Bitcoin deferred to Phase 4 - default, with one change from the brief: Avalanche added because both issuers are native there, BNB Chain kept but flagged bridged-only
- 2026-11-01 - BNB Chain USDT/USDC are Binance-Peg, not issuer contracts: freeze read is N/A, report states it plainly, asset authenticity module marks them `bridged` - verified during source check
- 2026-11-01 - Arbitrum and Polygon USDT are USDT0 (OFT). Freeze adapter for those two is gated behind a live ABI check in `verify:sources`; until confirmed the report shows `coverage: partial` for USDT on those chains rather than a false "clear" - verified during source check
- 2026-11-01 - Bot transport: Telegram (grammY) first, WhatsApp Cloud API in Phase 4 - default
- 2026-11-01 - Hosting: Railway (api, bot, postgres, redis), Netlify (web) - default, matches existing stack
- 2026-11-01 - Trace depth default 2 hops, hard cap 3, fan-out cap 25 counterparties per hop, known exchange hot wallets terminate the trace - default
- 2026-11-01 - Build sandbox has no RPC egress. All adapters have a `fixture` transport; CI runs on fixtures only; live verification runs via `pnpm verify:sources` on Punit's machine or Railway - constraint
- 2026-11-01 - EVM reads via `viem` (multicall where available), Tron via TronGrid HTTP, Solana via JSON-RPC `getAccountInfo` on the ATA - sensible defaults, swap-able
- 2026-11-01 - Monorepo: pnpm workspaces, TypeScript strict, tsup for packages, Vitest - per brief
- 2026-11-01 - Risk score 0-100 higher is worse; bands CLEAR/LOW/CAUTION/HIGH/BLOCK - per brief
- 2026-11-02 - Explorer order per EVM chain: Etherscan V2 when a key is set, then Blockscout hosted instance, then Routescan (Avalanche only). First provider that answers wins; errors from earlier providers are kept in the coverage detail - default
- 2026-11-02 - Fixture keys redact `apikey`, `api-key`, `api_key` query values so `CR_RECORD=1` can never commit a provider key - constraint
- 2026-11-02 - Solana transfers need a Helius key; a keyless path via `getSignaturesForAddress` + `getTransaction` was rejected for v1 (hundreds of RPC calls per screen on the public endpoint) - default, revisit if Helius free tier is withdrawn
- 2026-11-02 - Explorer data is fetched on every screen but scores nothing yet: one `FLOW_INBOUND_WINDOW` info line and an `explorer` coverage line. Fund-flow stays `disabled` so confidence cannot reach high before the trace exists - constraint
- 2026-11-02 - Screen by transaction: the sender of the pasted transfer is screened with amount and token contract taken from the tx; the receiver is confirmed when supplied. Sources (inbound counterparties of the sender) get label, OFAC and freeze checks on the top 10 by value and are informational until the scored trace exists - confirmed by Punit (feature request, surface: /check page; API endpoint added because the page needs one)
- 2026-11-02 - EVM tx resolution reads the receipt from the public RPC rather than an explorer API, so it needs no key and works on every registry chain - default
- 2026-11-03 - Trace fan-out is 25 per hop and the hop-2 expansion cap defaults to the same 25, so one screen can cost up to 26 explorer calls plus up to 50 freeze reads. Keyed Etherscan and TronGrid absorb that; keyless Blockscout may not. `CR_TRACE_EXPAND_CAP` lowers it per deployment - default, question 5 in QUESTIONS.md
- 2026-11-03 - Two different dust rules, on purpose: a counterparty whose transfers total under `CR_TRACE_DUST` (1 token unit) is dropped from the trace entirely (a sanctioned address dusting 0.1 USDT must not create exposure), while any kept counterparty in sanctioned, mixer or frozen floors at 8 points as SCORING.md says - default
- 2026-11-03 - A hard-blocked sender is not traced. The verdict is settled, the calls would be wasted, and `fund-flow` reads `not_applicable` so the BLOCK keeps `high` confidence - default
- 2026-11-03 - Only the OFAC list and labels mark a counterparty as sanctioned; the Chainalysis oracle is not called per counterparty (one eth_call each, same list upstream). Revisit if the lists ever disagree on a counterparty - default
- 2026-11-03 - "previously frozen", "fresh wallet" and "bridge-in" exposure categories exist in the tracer but only "bridge_in" can fire today (from a `bridge` label); the first two wait for the freeze event index and behavioural signals - constraint
- 2026-11-04 - Transaction count on EVM is the nonce (outbound transactions from the public RPC, no key), not the explorer's total; the evidence line says "outbound transactions". A receive-only wallet with nonce 0 is reported as such, which is what "fresh" means for a sender - default
- 2026-11-04 - A behavioural signal whose input is missing is "not evaluated" and named in the coverage line; it is never scored 0 silently and never penalised. Only a fully missing behaviour (no activity and no outbound) caps confidence at medium, so keyless deployments can still reach high - default
- 2026-11-04 - Contract-with-admin fires only when the explorer says the source is unverified. Unknown verification (no key, no Blockscout host) does not fire: a false "unverified" on a Safe or custody contract would be worse than a miss - default, question 7 in QUESTIONS.md
- 2026-11-04 - Approvals are read from Etherscan `getLogs` on the screened token only (key required) and from SPL delegates on Solana. Tron Approval events cannot be filtered by owner on TronGrid without scanning the whole token, so Tron is not evaluated yet - constraint
- 2026-11-04 - Outbound transfers cost one extra explorer call per screen on Blockscout, TronGrid and Tronscan; Etherscan and Helius serve both directions from one page, so no extra call there. Activity adds 2 to 4 small calls. `CR_BEHAVIOUR=0` removes all of them - default
- 2026-11-02 - TronGrid key is set on the Railway assay-api service (free tier). Tron lookups run keyed; Tronscan fallback stays in the code but needs its own key to be useful - confirmed by Punit
- 2026-11-05 - Label imports are committed files (`data/labels/imported-*.json`) produced by `pnpm import:labels`, not fetched at boot, so a report never depends on GitHub being up and every label in a report is traceable to a commit - default
- 2026-11-05 - Load order in `LabelStore` is name order with `seed.json` last, so a hand-kept seed entry always overrides an imported one for the same address (Binance 14 keeps its freeze note) - default
- 2026-11-05 - Exchange wallets from the imported datasets are labelled only when `data/vasps.json` gives the entity a decided status; `unknown` entities are skipped rather than guessed, because a wrong `exchange_licensed` hides a counterparty behind the KYC boundary and a wrong `exchange_unlicensed` costs 20 points - default, question 10
- 2026-11-05 - GPL data (ScamSniffer) is treated like non-commercial data: importer supports it, default path never loads it, output directory is git-ignored - default, question 9
- 2026-11-05 - MetaMask eth-phishing-detect is a domain list, not an address list; nothing imported, noted in LICENCES.md for the bot's link checks later - constraint
- 2026-11-06 - Freeze history is a committed local table (`data/freeze-index/<chain>-<symbol>.json`, built by `pnpm index:freeze`), not a log scan per screen: a Tether blacklist scan is a few thousand logs, a screen must not pay for it, and the same file serves the trace's 50 counterparties at zero cost. The directory is git-ignored for now because the sandbox cannot build it; Punit builds it live and decides whether to commit it (question 12) - default
- 2026-11-06 - Previously frozen is a hop-0 row at 20 points for the sender itself (`EXPOSURE_DIRECT_PREVIOUSLY_FROZEN`), the same weight as the counterparty category, not a hard block: the issuer looked and released, which is a fact worth 20, not 100. Scoring version 1.1.0 - default
- 2026-11-06 - When the live freeze read fails and the index still lists an address: a counterparty counts as `frozen` (60 points), the sender gets an info line and the `FREEZE_INDEX_SAYS_LISTED` flag but no points. The asymmetry is deliberate: 60 points of exposure is reversible on the next screen, a BLOCK verdict from a possibly stale table is not - default, question 11
- 2026-11-06 - Event signatures are computed from the Solidity signatures with viem (`AddedBlackList(address)` and friends), not hard-coded; Tether's events are not indexed (address in `data`), Circle's are (address in `topics[1]`). Avalanche USDt is assumed to emit the Tether set and is unverified - constraint, VERIFY.md step 7
- 2026-11-05 - Mixer and bridge seed addresses are written from memory of explorer tags and must be confirmed on etherscan before a demo (VERIFY.md step 6); the engine does not distinguish a confirmed label from an unconfirmed one, the `source` field does - constraint
- 2026-11-07 - Identity layer runs on a self-hosted moov-io/watchman (Apache-2.0) over its v2 HTTP API, through the same `Transport` as every other adapter, so it records and replays like the explorers. The adapter requires the v2 response shape (`entities[]`); a v1 answer (`SDNs`) is "unavailable", never "clear" - default
- 2026-11-07 - Originator screening is a hard-block source and runs in parallel with freeze, OFAC and the oracle, before the trace. `HB_ORIGINATOR_SANCTIONED` at or above `WATCHMAN_MIN_MATCH` (0.80), `IDENTITY_PEP` (15) when the hit's list name contains "pep", `IDENTITY_NAME_REVIEW` (info, flag `ORIGINATOR_NAME_REVIEW`, no points) between 0.59 and 0.80, `IDENTITY_NAME_CLEAR` otherwise. A near miss never blocks on its own - default, question 13
- 2026-11-07 - Coverage `watchman` exists only when an originator was supplied: `ok`, `disabled` when `WATCHMAN_URL` is unset (stated, no confidence change, the deployment chose it), `unavailable` when Watchman did not answer (caps confidence at medium: the VASP sent identity data and we could not check it). Report `identity` stays `attested` for supplied originator data; `verified` waits for a KYC attestation in Phase 4 - default
- 2026-11-07 - Only documented v2 query keys are sent (`type`, `name`, `birthDate`, `gov_national` as COUNTRY:ID, `address`, `minMatch`, `limit`); business registration numbers and LEIs are not, because Watchman answers HTTP 400 to a parameter it does not read and the exact keys are unverified. The LEI stays in the request schema for the GLEIF look-through later - constraint
- 2026-11-07 - docker-compose binds Watchman to 127.0.0.1:8084 and loads only the free official lists (`us_ofac,us_csl,eu_csl,uk_csl,un_csl`); OpenSanctions PEPs (CC BY-NC) are off. Image is the upstream `moov/watchman` build; the fork under the `moneybee-risk-datasources` submodule is the `build:` alternative, not the default, so a Railway deploy does not need the nested submodule - default, question 14
